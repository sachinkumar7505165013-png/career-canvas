ATS-Friendly Resume Formatting: What Actually Matters

CareerCanvas Editorial Team · 8 min read

"Applicant tracking system" gets used as a catch-all scare phrase — as if a piece of software is silently rejecting good resumes for arbitrary reasons. The reality is narrower and more useful to understand: an ATS is primarily a database and search tool. It stores your resume, tries to extract structured information from it (name, contact details, job titles, dates, skills), and makes that information searchable and filterable for a recruiter. Most rejections attributed to "the ATS" actually happen when a recruiter searches or filters and your resume doesn't match — not because a robot silently discarded it.

That distinction matters because it changes what you should actually fix. Here's what tends to genuinely cause problems, and what's mostly a myth.

Things that genuinely cause problems

Text inside images or graphics

If your job titles, skills, or contact information are part of an image, logo, or graphic element rather than actual selectable text, most systems can't extract them at all. This includes creative resume templates where the sidebar is a colored image block with text baked in. If you can't select and copy a piece of text with your mouse, an ATS probably can't read it either.

Multi-column layouts, done badly

Some systems read a page left-to-right, top-to-bottom, in a single pass. A two-column resume where your work experience is in one column and your skills are in a separate side column can get read out of order — for example, mixing a line from your experience section with a line from your skills sidebar into one garbled sentence. This is less of a problem with modern systems than it used to be, but it's still a real risk, especially with less common ATS platforms. If you use a two-column layout, keep it simple: one column for a photo and contact details only, with all substantive content (experience, education, skills as text) in the main column.

Uncommon file formats

A standard PDF (exported from a text-based document, not a scanned image) or a .docx file are both safe choices. Avoid formats like .pages, image-based PDFs (a scanned printout saved as PDF), or unusual export formats that some tools don't parse correctly.

Missing standard section headers

Systems often look for common header text — "Experience," "Education," "Skills" — to identify which section is which. A creatively renamed header like "My Journey" instead of "Experience" can make it harder for both software and a human skimming quickly to find what they're looking for.

Contact information formatted unusually

Putting your email or phone number inside a text box, header/footer area of a Word document, or as part of an icon graphic can cause it to be missed during parsing. Keep contact details as plain text in the main body of the document.

Things that are mostly myths

"Bold or colored text will break the ATS"

Reasonable use of bold, italics, or a single accent color for headers does not break parsing. What matters is that the underlying text is still selectable and in a sensible reading order — the visual styling on top of it generally doesn't interfere.

"You must use a completely plain, single-font resume"

A clean, well-organized resume with one or two fonts and clear section breaks reads fine both to software and to a human. You don't need to strip out all visual structure — you need to avoid burying information inside graphics or unconventional layouts.

"PDF files never work with ATS"

A text-based PDF (one where you can select and copy the text) is one of the most widely supported formats today. This myth largely comes from older or poorly built systems, and from scanned-image PDFs, which genuinely don't work — but a properly generated PDF is usually safe.

A practical formatting checklist

  • Every word on the page should be selectable, real text — not part of an image, icon, or graphic.
  • Use standard section headers: Experience, Education, Skills, Summary/Objective.
  • If you use a two-column layout, keep primary content (experience, education) in one main column; use a sidebar only for supplementary details like contact info or a short skills list.
  • Keep contact information as plain text in the main body, not in a header/footer or graphic.
  • Export as a text-based PDF or .docx rather than a scanned image or unusual file type.
  • Match some of the specific language from the job description where it's honest to do so — a resume that never mentions "project management" is unlikely to surface in a recruiter's search for that exact term, even if you've done the work.

Keyword matching still matters — but naturally

Beyond formatting, the biggest lever for showing up in recruiter searches is using the same terms the job posting uses, where they honestly apply to your background. If the posting says "Salesforce" and you've used Salesforce, write "Salesforce" rather than a more generic phrase like "CRM tools." This isn't about stuffing keywords in invisibly (some resumes try hiding keywords in white text — this is easy to detect, looks dishonest, and can backfire). It's about describing your real experience using the vocabulary the reader is already searching for.
